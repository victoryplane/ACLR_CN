# 06 · PSS 视频：提取、重压与重封装

> 本文讲如何把 ACLR（Armored Core: Last Raven）里的 PSS 视频提出来、改画面、再按原版结构封回去并写回 ISO。
> PSS 不是私有封装，本质就是 MPEG-2 Program Stream；真正的难点在「重封装要让游戏 demuxer 认」，
> 其中流结束码 `00 00 01 B9` 的位置决定了游戏播完是正常转场、卡死、还是黑屏十几秒。

## 背景与目标

ACLR 的 CG（开场、结局 staff roll、按键演示等）以 `.PSS` 文件存放在 ISO 的影片目录里。字节级拆解后确认：

- PSS = MPEG-2 Program Stream（MPEG-PS / PS），文件直接从 pack 起始码 `00 00 01 BA` 开始，没有额外的自定义头。
- 视频轨：MPEG-2 视频基本流（m2v），流 id `0xE0`；ACLR 的对象为 640×448 @ 30fps，码率约 6~7.5 Mbps。
- 音频轨：PS2 ADPCM，走私有流 id `0xBD`；FFmpeg 不会自动识别它，音频不要交给 FFmpeg 重解。

汉化要处理的是「烧进画面」的日文字幕，所以必须动视频像素：提取 → 重压画面（或替换画面）→ 按原版结构重封装 → 回写 ISO。
音频建议原样保留、不重压。

## 前置依赖

- Python 3.x（读写与字节解析只用到标准库）。
- FFmpeg（需含 `mpeg2video` 编码器与 `-f vob` 封装，请自行安装）。
- 自备合法持有的游戏 ISO；自备能跑 PS2 的模拟器（如 PCSX2）用于最终实测。
- 能搜十六进制串的工具（或直接用 Python）做字节级自检。

## 一、PSS 结构：定长 pack 是硬约束

对原版文件做字节级拆解，得到以下关键事实（ACLR 实测）：

| 项 | 值 / 结构 |
|---|---|
| 封装 | MPEG-2 Program Stream，起始码 `00 00 01 BA` |
| pack 头 | 14 字节：起始码 4B + SCR 6B + mux_rate 3B + stuffing 1B |
| mux_rate | `0x012663`（从原版 pack 头模板里保留） |
| stuffing_length | 0（pack 头末字节 `0xF8`） |
| pack 长度 | 固定 16384 字节 |
| pack 内容 | 多个 PES 背靠背铺满，PES 不跨 pack 边界（原版视频 pack 常见 4 个视频 PES、每个约 4090 B） |
| 填不满时 | 用 `0xBE` padding 流补齐：`00 00 01 BE + 2B长度 + 0xFF×长度` |
| SCR | 大致按 `3000 × ((pack序号+1)//2)` 前进，尾部偶有 VBV 修正、不倒退 |
| 视频结束 | `00 00 01 B7`（sequence_end）塞进最后一个视频 PES 的 payload 内，不是独立 PES |
| 文件结束 | 末尾 4 字节 `00 00 01 B9`（program_end） |

音频侧细节：`0xBD` 私有流首包带 SShd 头（记录 48 kHz、双声道、interleave 0x200 等信息），
SSbd 里写的是整段音频的总字节数。重封时不要动音频，把原版音频 PES 原样取回即可。

两条必须分清的「结束」语义：

- `00 00 01 B7`（sequence_end）是**视频基本流**的结束标记；
- `00 00 01 B9`（program_end）是**整条 PS 流**的结束标记，游戏内的 demuxer 就靠它判断「播完了、可以转场」。

## 二、提取

ISO9660 目录给每个文件一个 LBA（逻辑块地址，1 块 = 2048 字节）和字节大小。
PSS 文件从 `LBA × 2048` 处开始、长度 `size` 字节。提取就是一次 seek + read：

```python
with open("game.iso", "rb") as f:
    f.seek(lba * 2048)      # lba 来自你自己 ISO 的文件表
    data = f.read(size)     # size 单位字节
    open("movie.pss", "wb").write(data)
```

`lba` 与 `size` 可以从 ISO9660 目录解析，也可以从解包工具生成的文件清单里拿，来源不影响结果，
只要数值准确即可。提取后先核对文件开头是不是 `00 00 01 BA`。

## 三、重压画面（改字幕）

画面改动分两类，均需先解出视频帧：

1. **加字幕（hardsub）**：用 FFmpeg 的字幕滤镜（`subtitles`/`drawtext`）把中文字幕渲染进画面，再编码回 MPEG-2。
2. **擦除原字幕**：对含字幕的那几帧做 inpainting 抠掉日文、在原位补中文。逐帧抠图没有通用一条命令，需按自己的工具链自行实测。

重编码约束（PS2 解码器兼容性）：

- 分辨率与帧率保持与原版一致（ACLR 为 640×448 @ 30fps）；
- 码率保守（原版约 6~7.5 Mbps，别盲目拉高）；
- 音频不要重压：直接沿用原版 ADPCM 音频 PES。

把新视频直出成 vob，以便携带 PTS/DTS：

```
ffmpeg -y -i 编辑后的画面.mkv -map 0:v:0 -c:v mpeg2video -b:v 6000k \
  -s 640x448 -r 30 -f vob video.vob
```

（参数按实际源改成与原版一致的分辨率/帧率。）

两个 FFmpeg 陷阱提前说明：

- `mpeg2video` 编码器**不会**在流末尾输出 `00 00 01 B7`（sequence_end），要自己塞进最后一个视频 PES。
- 若从裸 m2v 用 `-c:v copy -f vob` 包一层，得到的 vob **没有 DTS**，无法用于音视频交错；
  必须用 `-c:v mpeg2video ... -f vob` 重新编码直出（编码阶段生成 PTS+DTS）。

## 四、重封装：复刻原版结构

重封的目标不是「能播」，而是「游戏 demuxer 认」。按下面顺序做：

1. **保留 system header**：从原 PSS 里找 `00 00 01 BB` 那一段，整段原样复制，放进第一个 pack。
   优先复制原版；不要凭感觉重建，除非原文件确实没有。
2. **保留 pack 头模板**：取原 PSS 第一个 pack 头（`00 00 01 BA` 到下一个起始码之间的 14 字节）作模板，
   重封时只改写其中的 SCR 字段，保留 mux_rate 与 stuffing_length。
3. **解析原音频**：取 `0xBD` 流的 PES 及其 PTS，原样保留。
4. **解析新视频**：取 vob 里 `0xE0` 流的 PES，读 PTS/DTS。
5. **对齐时间轴**：FFmpeg 的 vob 混流会给视频 PTS 加一个起始延迟。计算
   `offset = 视频起始PTS − 音频起始PTS`，把视频 PES 头的 PTS/DTS 各回减 offset，使音视频落在同一时间轴。
6. **按 DTS 交错**：视频用 DTS 作排序键（续包无 DTS 时沿用上一包），音频用 PTS，两路按时间归并。
7. **定长打包**：每 16384 字节一个 pack。写 pack 头（模板 + 按该包首个 PES 时间戳计算的新 SCR），
   然后把 PES 背靠背塞进去；放不下就 `0xBE` padding 填满当前 pack、另起一个 pack。
   **PES 绝不跨 pack 边界**。system header 只在首个 pack 出现一次。
8. **塞 sequence_end**：把 `00 00 01 B7` 追加进最后一个视频 PES 的 payload（不是独立 PES），
   并把该 PES 的长度字段 +4。
9. **收尾**：最后一个内容 pack 之后**立即**写 `00 00 01 B9`。不要在其前面垫长 padding（见「坑与教训」）。

> 一句话：pack 头、system header、音频都从原版继承；只有视频 PES 换成新的，
> 并按原版的「定长 pack + DTS 交错 + 结束码布局」重新铺一遍。

## 五、回写 ISO

回写时文件大小可能变化，分两种情况：

**A. 原位等长写回（size 不变）**

只有新内容 ≤ 原文件大小时才可用。做法：内容按原结构铺好，剩余空间用 `0xBE` padding 补齐到原 size，
但 **padding 必须放在 `00 00 01 B9` 之后**（即「内容 + B9 + padding」），LBA 与 extent 全部不变。
这种方式简单、不牵动其他文件，但会保留无用的 padding 空间。

**B. 真缩短 + 后续文件前移（size 变小）**

新内容明显变小时更干净的做法：

1. 把文件截到最后一个内容 pack 结束（内容按 2048 字节扇区对齐），再补 4 字节 `00 00 01 B9`；
2. 计算释放的扇区数 = 旧文件占用扇区数 − 新文件占用扇区数（文件占用扇区数按 `ceil(size/2048)` 计）；
3. 把其后**所有**文件整体向前移动同样的扇区数；
4. 更新 ISO9660 extent：缩短文件的新 size、以及每个被移动文件的新 LBA，**LE 与 BE 两种端序都要改**；
5. 截断 ISO 到新长度。

实测例子（ACLR 开场 CG）：真实内容只占 53.9%（77,108,839 B），其余 62.9 MB 是 padding；
按方案 B 缩短后文件 77,119,492 B，后续文件整体前移 32,200 扇区（65,945,600 B），ISO 缩小约 66 MB。
extent 的编辑细节见 `05-打包与ISO.md`。

> 动手前先确认：游戏读视频是**按目录文件名**还是**硬编码 LBA**。若硬编码 LBA，前移会破坏引用，
> 需要另想办法。这一点需针对目标游戏自行实测。

## 六、自检清单

1. **播放器粗检**：用支持 MPEG-PS 的播放器（mpv/VLC）播一遍，看画面、音画同步、结尾是否正常。
   注意播放器通常比游戏 demuxer 宽容，这一步通过 ≠ 游戏通过。
2. **模拟器实测**：在模拟器里让 CG 从头播到结尾，确认最后画面结束后**立即**进入下一阶段，
   不卡死、不长黑屏。这是最终判据。
3. **字节级 tail 检查**：
   - 找 `00 00 01 B7`，确认它在最后一个视频 PES 的 payload 内；
   - 找 `00 00 01 B9`：
     · 真缩短模式：它应是文件最后 4 字节；
     · 等长模式（本仓 `tools/pss_remux_v3.py` 已实现为 B9 前置）：它紧跟最后一个内容
       pack，**B9 之后**只剩 padding；
   - 看 B7→B9 的距离：原版内容铺满文件，B7、B9 都在约 99% 处、相距仅约 18 KB；
     若 B9 前面躺着几十 MB 的 `0xBE/0xFF` padding，就是「坑 2」的病状。
4. **回写核对**：若走了前移，重查每个被移动文件的 extent（size/LBA，双端序），并确认 ISO 可启动、其他文件可读。

## 坑与教训

### 坑 1：变长 pack / 一包一 PES → 播完黑屏卡死

- **现象**：重压后视频画面正常，但播到最后黑屏卡死、不进转场；原版视频转场正常。
- **根因**：某种重封方式把 PS 封成「变长 pack（约 2KB 一包、一包一个 PES）」，而原版是固定 16384 字节 pack、
  每包背靠背铺多个 PES。游戏 demuxer 能从变长结构解出画面，却没正确消费结束信号 `00 00 01 B9`，于是播完不结束。
- **规避**：复刻原版定长 pack 结构；不要用「变长一包一 PES」重封 PSS。

### 坑 2（重点）：B9 之前垫长 padding → 播完黑屏十几秒才转场

- **现象**：播完最后画面后，黑屏约十几秒（PS2 4x DVD 的读盘时间）才进下一阶段。
- **根因**：为「原位等长写回」，把重压后省出来的空间用纯 `0xBE` padding（内容 0xFF）补齐到原文件大小，
  并把 `00 00 01 B9` 放在文件最末尾。重压码率低时，真实内容只占一半出头，后面几十 MB 全是 padding，
  且 **padding 在 B9 之前**。游戏 demuxer 以 `00 00 01 B9` 为结束信号，播完最后画面后还要把这几 MB padding
  全部读/解复用完才碰到 B9 → 黑屏。观察该区 SCR 恒不前进，可确认延迟来自读盘/解复用，而非时间戳等待。
- **规避**（二选一）：
  1. **保持等长**：`00 00 01 B9` 紧跟最后一个内容 pack，padding 放到 B9 之后（`内容 + B9 + padding`），
     LBA/extent 不变，安全但浪费空间；
  2. **真缩短**：截到最后一个内容 pack（扇区对齐）+ B9，后续文件整体前移、更新 extent、截断 ISO（见「回写」方案 B）。
- **数字对照**：原版 B7 与 B9 都在约 99% 处、相距仅约 18 KB；病状版 B9 前躺着 62.9 MB 死 padding。

### 坑 3：FFmpeg 不输出 sequence_end

- **现象**：`mpeg2video` 编码器不在流末写 `00 00 01 B7`。
- **规避**：自己把 `00 00 01 B7` 追加进最后一个视频 PES 的 payload，并把该 PES 长度 +4。

### 坑 4：`-c:v copy -f vob` 没有 DTS

- **现象**：裸 m2v 用 `-c:v copy -f vob` 包出来的 vob 无 DTS，交错会乱。
- **规避**：用 `-c:v mpeg2video ... -f vob` 重编码直出，编码阶段生成 PTS+DTS。

### 坑 5：音频交给 FFmpeg 会丢

- **现象**：PS2 ADPCM（`0xBD` 私有流）FFmpeg 不自动识别。
- **规避**：音频从原 PSS 原样取回 PES，不重解、不重压。
